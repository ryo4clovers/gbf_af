# Requirements

## 目的

Granblue Fantasy のアーティファクト情報を取得し、ユーザーがローカルで管理・評価・CSV 出力できるようにする。

## 機能要件

### R-001: アーティファクト一覧取得

- ユーザーがアーティファクトページを開いている状態で、現在ページの一覧 API を取得する。
- 取得対象は読み取り専用 GET リクエストのみ。
- ページ遷移はユーザーが手動で行う。

### R-002: スキャン進捗管理

- 現在ページ
- 最終ページ
- 取得済みページ
- 総件数
- 最終スキャン日時

を保存・表示する。

### R-003: ローカル保存

- 取得したアーティファクトデータを Chrome Extension のローカルストレージに保存する。
- 同一 `id` のアーティファクトは上書き更新する。
- 削除検知は初期実装では必須としない。

### R-004: 管理画面

専用ページ `dashboard.html` を提供する。

管理画面では以下を行えること。

- 一覧表示
- フィルタ
- ソート
- 必要 / 不要チェック
- スコアルール設定
- CSV 出力

### R-005: スコアルール設定

ユーザーが独自にスキルごとの重みを設定できる。

例:

- スキル名
- スキル ID
- 攻撃寄り評価
- 防御寄り評価
- 特殊評価
- 除外条件
- 加点 / 減点

### R-006: CSV 出力

ローカル保存済みデータを CSV として出力する。

初期カラム案:

- 所持 ID
- アーティファクト種別 ID
- 名前
- 種類
- 属性
- レベル
- ロック状態
- 必要 / 不要
- 装備キャラ
- ゲーム内攻撃スコア
- ゲーム内防御スコア
- ゲーム内特殊スコア
- ゲーム内合計スコア
- 独自スコア
- スキル 1 名前
- スキル 1 値
- スキル 1 品質
- スキル 2 名前
- スキル 2 値
- スキル 2 品質
- スキル 3 名前
- スキル 3 値
- スキル 3 品質
- スキル 4 名前
- スキル 4 値
- スキル 4 品質

## 非機能要件

### NFR-001: 安全性

- ゲーム画面を操作しない。
- ゲーム画面の UI を変更しない。
- 状態変更 API を呼ばない。
- 外部送信しない。

### NFR-002: 保守性

- API レスポンス型と内部モデルを分離する。
- 正規化処理を独立させる。
- スコア計算を UI から分離する。
- CSV 生成を UI から分離する。

### NFR-003: デバッグ性

- 取得した生 JSON を必要に応じて確認できる構造にする。
- API 取得エラー、パースエラー、保存エラーを区別する。
- 失敗時はユーザーに短い説明を出す。

## 対象外

- 自動周回
- 自動売却
- 自動強化
- 自動装備
- ゲーム画面の改変
- 他ユーザーとのデータ共有
- クラウド同期
